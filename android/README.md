# Android 农场助手

APK 使用 Kotlin 原生实现支付宝、淘宝和挪了个箭流程，不再嵌入 Python，也不把功能参数转给 Python CLI。运行时通过 Android 无障碍服务完成本机截图、中文 OCR、手势、返回及应用启动，不需要电脑、ADB、Root 或服务器。

OCR 在 APK 内使用与桌面 RapidOCR 3.10.0 相同的 PP-OCRv6 模型和后处理：ONNX Runtime Android 执行推理，OpenCV 做图像处理，Clipper 6.4.2 扩张文字框。农场运行读取应用私有目录 `files/cli-output/babanongchang.toml`，文件缺失时使用默认值；相对诊断路径以 `files/cli-output` 为基准。

## 功能对应

| APK 选择 | 对应行为 | 参数 |
| --- | --- | --- |
| 一键照料 | 自动检测支付宝／淘宝；支付宝优先，再运行淘宝 | 肥料阈值、最多施肥次数、浏览时长、淘宝置信度 |
| 连续施肥 | 在支付宝农场使用肥料 | 肥料阈值、最多施肥次数 |
| 逛农货 | 浏览农货并返回 | 浏览时长 |
| 领取任务 | 执行支付宝任务池 | 浏览时长 |
| 淘宝农场 | 从主页进入芭芭农场并执行已支持的肥料任务 | 识别置信度 |
| 挪了个箭 | 进入游戏后辅助解题 | 安全／快速、目标关卡、通关次数、时限、复活广告、连胜、重开限制、棋盘区域与诊断 |

原有单次施肥验证入口保留，它使用独立的严格页面验证，不代表连续流程也具有相同的单次限制或余额减少确认机制。

## 使用

1. 安装 APK，在系统设置中手动授权无障碍服务。首页显示服务连接状态，连接后收起首次使用说明。
2. 在首页功能卡片中选择照料或游戏功能，点击“开启小白球”。此操作只准备控制入口，不会开始自动化。需要调整时，长按功能模块进入专属设置页；首页和小白球功能列表均支持此操作。
3. 小白球可以拖动，松手后吸附到屏幕左右边缘。点击展开面板，可以切换功能，点击“收起面板”或面板外部恢复小白球；“移到另一侧”提供无需拖动的位置调整。
4. 全部流程自行启动支付宝／淘宝；单项支付宝流程需手动进入农场，挪了个箭需手动进入游戏。自行登录、解锁并保持目标页面前台，再从面板手动开始。运行时浮层隐藏，音量上暂停，音量下结束；也可从应用重新显示小白球进行控制。运行期间保持亮屏，不要手动改变页面。
点击开始后，屏幕中央显示浅灰圆形的 3 → 2 → 1 倒计时。下方“取消”取消本次启动并恢复小白球，“跳过”立即结束倒计时并开始任务；倒计时自然结束后先移除面板，再启动任务。倒计时期间不执行任务，服务中断或控制浮层被移除时取消待启动任务。暂停后的“继续”不重复倒计时。

5. 任务正式开始后自动保持亮屏，包括高级工具中的单次施肥验证；暂停、请求终止、任务完成或失败、返回退出首页、从最近任务中移除 App，以及无障碍服务断开时，释放亮屏并恢复系统息屏规则，继续任务时重新保持亮屏。正常切换到支付宝／淘宝执行任务不取消亮屏。暂停后点击小白球，从面板继续或结束。暂停不消耗等待时限；若继续后即将使用暂停前的页面坐标，本轮会停止，需重新开始以识别页面，避免执行旧坐标。已发出的手势无法撤销。
6. 完成、失败或结束后恢复小白球。当前状态在首页展示。打开“记录日志”后，日志通过首页独立的“运行记录”入口查看；诊断导出和原单次施肥验证位于“高级设置与工具”。结束时等待后台任务退出，退出完成前不能开始另一轮。

各功能独立保存设置，修改有效值后自动保存，下次运行生效；无效数值会就地提示并保留上次有效配置。旧版全局“自定义运行参数”不再读取，首页移除参数输入和命令说明。

- 一键照料：停止施肥的肥料余额、最多施肥次数、浏览时长、淘宝识别置信度。
- 连续施肥：停止施肥的肥料余额、最多施肥次数。
- 逛农货、领取任务：各自的浏览时长（至少 15 秒）。
- 淘宝农场：识别置信度；与一键照料共用淘宝识别设置，范围 0.00～1.00、默认 0.75，松手保存，可恢复默认。
- 挪了个箭：安全／快速模式、目标关卡、通关次数、最长运行时间、点击间隔、页面等待时限、重开次数、复活广告与等待时限、连胜策略、棋盘范围、仅识别当前画面，不点击。指定目标关卡后，通关次数和运行时限不再作为停止条件。

本机截图、OCR 和点击直接使用无障碍服务。平台限制截图最短间隔为 500ms，游戏快速模式仍使用 300ms 点击间隔。

## 运行记录与诊断

首页“记录日志”开关默认关闭。关闭时不写运行记录、`cli.log` 和事件日志，当前状态仍显示在首页。打开后，下次正式开始才把功能名称、开始时间、参数、日志及结束结果保存到 `files/cli-output/runs/<记录 ID>/`，并兼容保留 `cli.log`。挪了个箭的诊断截图、标注和 JSON 报告仍写入应用私有目录 `files/cli-output`；事件日志只在开关打开时写入。首页不展示日志正文；“运行记录”列表按开始时间倒序排列，点击查看完整日志详情。运行中可点击刷新；应用异常退出且未保存结束结果时标注为中断。倒计时取消不产生记录。历史记录不被后续运行覆盖。结束运行后点击“导出诊断”可保存 ZIP。相对输出路径以此诊断目录为基准，导出会包含其子目录；自定义到其他绝对路径的产物不在默认导出范围。

中文模型随 APK 打包，无网络权限，不上传截图或日志。诊断可能包含目标应用页面内容；只在用户手动选择的位置导出。清除应用数据会删除私有诊断文件。

## 与桌面对齐的离线 OCR

APK（含旧单次施肥入口）在 Kotlin 中实现 RapidOCR 3.10.0 的图像预处理、文字检测、方向分类、识别、字典解码、文字框处理和置信度过滤。模型为默认的 PP-OCRv6 small 检测／识别和 mobile 方向分类；不再使用 ML Kit，也不再调用 Python。

Android 通过 ONNX Runtime Android 1.24.3 的 CPU 接口执行张量推理，OpenCV 4.12 做缩放、轮廓和透视裁剪。文字框扩张使用与桌面 pyclipper 相同的 Clipper 6.4.2 原始源码。现有置信度过滤与淘宝滑动条继续有效，识别引擎默认也会过滤低于 0.5 的结果，因此滑动条低于 0.5 不会恢复已被引擎过滤的文字。

构建任务 `prepareOcr` 通过仓库锁定的 uv 环境准备桌面 CLI 的三份模型，复制到 APK 资源 `ocr/` 并生成 SHA-256 清单 `ocr/manifest.json`。首次构建可能下载模型；运行时只使用包内模型，不下载模型，不需要网络。跨平台 OpenCV／ONNX Runtime 版本不同，不承诺任意截图的结果逐位相同。

## 构建与验证

需要 JDK 17、Android SDK 36、NDK、CMake 3.22+、Gradle Wrapper 和 uv。uv 只在构建时准备 OCR 模型，APK 运行时不需要 Python。首次构建需要下载 Gradle、OpenCV、ONNX Runtime 及 OCR 模型。

```sh
cd android
./gradlew assembleDebug lintDebug
```

产物：`app/build/outputs/apk/debug/app-debug.apk`。支持 Android 11+ 的 arm64-v8a／x86_64；不支持 32 位设备。APK 不包含 Python。桌面 CLI 仍由 uv 管理 Python 3.14。

无设备冒烟不会唤醒或操作设备：

```sh
uv run babanongchang --help
```

**验收限制：** 本轮构建与本地测试不等于实体手机验收。支付宝／淘宝真实页面、完整游戏流程、音量键可靠接收与拦截、厂商无障碍兼容性仍需真机验证。旧版单次施肥模拟器记录不能作为本版全套流程通过的证据。连续流程沿用原有消费与重试规则；请在连续施肥设置页限制最多施肥次数，控制首次实际运行范围。
