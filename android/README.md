# Android CLI 全功能版

APK 内嵌 Python，构建时直接打包仓库 `src/babanongchang`，与桌面 CLI 共用自动化流程、任务池、页面等待和游戏算法。运行时通过 Android 无障碍服务完成本机截图、中文 OCR、手势、返回及应用启动，不需要电脑、ADB、Root 或服务器。

## 功能对应

| APK 选择 | CLI 对应 | 行为与参数 |
| --- | --- | --- |
| 全部流程 | `all` | 自动检测支付宝／淘宝；支付宝优先，再运行淘宝 |
| 支付宝：连续施肥 | `fertilize` | `--threshold`、`--max-clicks` |
| 支付宝：逛农货 | `goods` | `--browse-seconds` |
| 支付宝：任务池 | `tasks` | 共用 `TASK_POOL` 与全部已注册执行器 |
| 淘宝：完整流程 | `taobao` | 主页导航、任务与施肥，与 CLI 保持一致 |
| 游戏：麻将 | `games --majiang` | 免费磁铁、广告与连续闯关 |
| 游戏：挪了个箭 | `games --nlgj` | safe／fast、目标关卡、通关次数、时限、复活广告、连胜、重开限制、棋盘区域与诊断 |

原有单次施肥验证入口保留，它使用独立的严格页面验证，不代表新的连续 CLI 流程也具有相同的单次限制或余额减少确认机制。

## 使用

1. 安装 APK，在系统设置中手动授权无障碍服务。
2. 打开 APK 选择功能，填写附加 CLI 参数；无需输入命令、模块名或游戏标志。参数保存在本机，完整参数可从“查看完整 CLI 参数”查看。
3. 点击“保存选择并显示控制浮层”。全部流程自行启动支付宝／淘宝；单项支付宝流程需手动进入农场，麻将／挪了个箭需手动进入游戏。自行登录、解锁并保持目标页面前台。
4. 从浮层点击“开始所选流程”。运行时浮层隐藏，音量上暂停，音量下结束。也可从应用重新显示浮层进行控制。运行期间保持亮屏，不要手动改变页面。
5. 暂停后只能从浮层继续。暂停不消耗等待时限；若继续后即将使用暂停前的页面坐标，本轮会停止，需重新开始以识别页面，避免执行旧坐标。已发出的手势无法撤销。
6. 完成、失败或结束后恢复浮层，APK 内可查看日志；结束时等待后台任务退出，退出完成前不能开始另一轮。

主页的“淘宝 OCR 置信度阈值”滑动条支持 0.00～1.00，步长 0.01，默认 0.75；滑动时只更新数值，松手后保存。“重置淘宝置信度”恢复到 0.75 并立即保存。设置在下一轮运行开始时读取，当前运行不变。仅影响 APK 淘宝流程（包含全部流程中的淘宝部分），不影响支付宝、游戏及桌面 CLI。较低阈值可保留更多 OCR 文字，但增加误识别风险；本机农场页面识别不到时可谨慎调低后重试。

附加参数示例：

```text
# 连续施肥：余额阈值 600，最多点击 3 次
--threshold 600 --max-clicks 3

# 挪了个箭：安全模式，最多通关 3 次或运行 15 分钟
--mode safe --levels 3 --max-minutes 15

# 挪了个箭：快速模式，完成目标关卡后结束
--mode fast --target 100

# 挪了个箭：仅识别当前设备画面，不点击
--dry-run

# 禁止复活广告及连胜金币操作
--no-revive-ads --streak-policy stop
```

`--serial` 和自定义 `--adb` 属于电脑连接配置，APK 会拒绝它们。本机截图、OCR 和点击直接使用无障碍服务。平台限制截图最短间隔为 500ms，游戏 fast 模式仍使用 CLI 的 300ms 点击间隔。

## 离线截图与诊断

“选择截图用于离线识别”通过系统文件选择器导入图片，并自动准备 `games --nlgj --screenshot ... --ocr`。保存选择并从浮层开始后，会生成标注图与 JSON 报告；不截取或操作目标应用。

挪了个箭沿用 CLI 的诊断截图、标注、JSON 报告和事件日志。默认保存在应用私有目录 `files/cli-output`，普通运行日志为该目录的 `cli.log`；界面展示最近约 2 万字符。结束运行后点击“导出诊断”可保存 ZIP。相对 `--output` 路径以此诊断目录为基准，导出会包含其子目录；自定义到其他绝对路径的产物不在默认导出范围。

中文模型与 Python 依赖随 APK 打包，无网络权限，不上传截图或日志。诊断可能包含目标应用页面内容；只在用户手动选择的位置导出。清除应用数据会删除私有诊断文件。

## 构建与验证

需要 JDK 17、Android SDK 36、Gradle Wrapper，以及可由 PATH 找到的 Python 3.10（或通过 Chaquopy 的 `buildPython` 配置）。首次构建需要下载 Gradle、Chaquopy 和 Python 依赖。

```sh
cd android
./gradlew testDebugUnitTest assembleDebug lintDebug
```

产物：`app/build/outputs/apk/debug/app-debug.apk`。支持 Android 11+ 的 arm64-v8a／x86_64；不支持 32 位设备。APK 内使用 Python 3.10、NumPy 1.26.2 和 OpenCV 4.5.1.48，以适配可用的 Android 预编译包；使用 tomli 兼容 TOML。桌面 CLI 仍由 uv 管理 Python 3.14。

桌面回归测试不需要手机，不会唤醒或操作设备：

```sh
uv run python -m unittest discover -s tests
uv run babanongchang --help
```

Android 控制状态单元测试覆盖暂停时间、旧页面坐标失效、暂停后结束与长等待取消；Python 适配测试覆盖各模块路由、本机 OCR、缩放坐标、前台变化、离线报告及取消时钟。OCR 使用 ML Kit 原始行置信度，继续应用共享代码的置信度阈值；不同 OCR 模型仍可能产生不同识别结果。

**验收限制：** 本轮构建与本地测试不等于实体手机验收。支付宝／淘宝真实页面、完整游戏流程、音量键可靠接收与拦截、厂商无障碍兼容性仍需真机验证。旧版单次施肥模拟器记录不能作为本版全套流程通过的证据。连续流程沿用 CLI 的消费与重试规则；请通过 `--max-clicks` 等参数控制首次实际运行范围。
